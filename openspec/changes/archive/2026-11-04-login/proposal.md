# Proposal

## Why

Приложением хотят пользоваться друзья, а сейчас все видят одни и те же контакты: входа нет, данные общие. Нужно, чтобы каждый входил под своей почтой по ссылке из письма и видел только свои контакты, заметки и группы. Источник требований - `specs/02-пользователи-вход.md`.

## What Changes

- Вход только по ссылке из письма (Better Auth, MagicLink): страница входа с полем почты и кнопкой «Получить ссылку», первый вход - он же регистрация, паролей нет
- Правила ссылки: работает один раз и 15 минут, новая ссылка гасит старые, не больше 3 писем на одну почту за 10 минут, ответ не выдаёт, есть ли такой пользователь
- Сессия держится 30 дней с последнего захода, можно с нескольких устройств; в шапке почта пользователя и кнопка «Выйти» (выход только на этом устройстве)
- Без входа приложение не открывается: любая страница ведёт на страницу входа; права проверяются на сервере в каждом запросе к данным
- Письмо «Вход в Личную CRM» от «Личная CRM» отправляет Nodemailer: локально и в автотестах - в заглушку Mailpit, на сервере - через Resend; куда слать, решают настройки, а не код
- **BREAKING** У каждого контакта и группы появляется владелец; список, поиск, карточка, заметки, группы, фильтр и блок «Пора связаться» показывают только данные текущего пользователя. Чужой контакт по прямой ссылке - «Контакт не найден»
- **BREAKING** Названия групп уникальны в пределах одного пользователя, а не во всей системе: у A и B может быть по группе «Друзья»
- Миграция данных: все существующие контакты, заметки и группы переходят пользователю с почтой из настройки `OWNER_EMAIL`; ни одна запись не теряется. Демо-данные тоже создаются у этого пользователя
- Новый пользователь видит пустой список и подсказку «Добавь первый контакт»
- Автотест главного сценария из `specs/01-продуктовая-идея.md` сначала входит под пользователем; вход проверяет отдельный автотест на двух пользователях
- Откат этой выкатки - только вместе: база из копии перед выкаткой и прошлая версия приложения; порядок описан в README

## Capabilities

### New Capabilities

- `user-auth`: вход по ссылке из письма, письмо со ссылкой, ограничения ссылки и частоты писем, сессия и выход, закрытый без входа доступ
- `data-ownership`: владелец у контактов и групп, видимость и изменение только своих данных везде, перенос существующих данных владелице

### Modified Capabilities

- `contact-groups`: уникальность названия группы и «все группы» теперь в пределах одного пользователя

## Impact

- База: новые таблицы Better Auth (пользователи, сессии, аккаунты, проверочные токены) и учёт отправленных писем; колонка владельца в `contacts` и `groups`; уникальный индекс названий групп - по владельцу. Миграция меняет существующие данные - показать до merge
- Код: `src/lib/contacts.ts` и все server actions получают текущего пользователя; новые страницы входа и «Ссылка устарела»; шапка; `proxy.ts` для перенаправления на вход; обработчик `/api/auth/*`
- Новые библиотеки: `better-auth`, `nodemailer` (обе названы в спеке)
- Локально: в `compose.yaml` добавляется Mailpit; новые строки в `.env` и `.env.example`
- Сервер: новые строки в `/opt/personal-crm/.env` (секрет Better Auth, адрес приложения, подключение к Resend, отправитель, `OWNER_EMAIL`), `deploy/compose.yaml` передаёт их приложению и разовому контейнеру миграций
- Человек: аккаунт Resend, подтверждение домена `mail.crm.vupsen.space` и его записи DNS, ключ Resend в `.env` сервера
- CI: Mailpit как сервис в задаче Playwright, тестовые значения настроек входа
- Тесты: все логические и e2e-тесты работают от имени пользователя
